# Медиа-инструменты: видео-хувер, кадры, правка изображений

**Статус:** план 2026-11-24. Порядок работ: **видео-хувер** → **последовательность кадров и сетка** → **правка
изображений**. Ниже — предварительные решения (не предположения: где факт не проверен, это сказано явно), последствия
для остального приложения и список спайков, которые надо провести до кода.

## 0. Что уже есть

- Правая панель главного окна: у видео кадр + ▶, `Save frame` до и после проигрывания (0.1.21).
- Меню видео-результата: `Save Frame at …` (момент совпадения) и `Copy Frame` (PNG в буфер) — 0.1.20.
- Space в главном окне: большой просмотр, видео играет с момента, `Save frame` берёт текущий кадр.
- Панель по хоткею (`index.html` + `panel.js`): быстрый поиск «поверх» других программ, свой маленький список и свой
  Space-просмотр. **Инструменты туда не добавляем** (транзитная, клавиатурная поверхность).
- Панель по хоткею: **визуальный баг углов исправлен** — причина и проверка в §5.

## 1. Видео-хувер (следующее)

Всплывающий под курсором плеер в главном окне результатов — то, что в Imagus-Mass-Download-Mod сделано для видео.

Проверено по коду (2026-11-24), до реализации:

- **Ховер есть только у карточек сетки**: `peekOnHover` зовётся из `cell()`; `tableRow()` ховера не имеет, а строка во всю
  ширину — «сбоку от строки» места нет. **Решение: в таблице плеера нет** (там клик и Space, как сейчас); панель по
  хоткею и боковая панель — тоже нет (в боковой уже есть плеер).
- Ховер картинок: 300 мс на `pointermove`, закрытие на `pointerleave`. Плеер — тот же ритм, но с паузой 250 мс, чтобы
  успеть перейти зазор 12 px до кнопок.
- Прямоугольник карточки (`getBoundingClientRect`) даёт позицию. Область результатов — `#content`
  (`overflow-y: auto`), справа `#side` 324 px, снизу `#batch`. **Решение: границы — прямоугольник `#content`, не окна**;
  иначе закреплённый плеер накрыл бы боковую панель и панель операций.
- `renderOf(video)` = `["video", hit.loc ?? 0.5]`; `loc` есть только у хита-кадра (сегмент), у найденного по имени его
  нет. `render` умеет отдавать кадр видео как data-URL — fallback не требует нового op'а.
- Видео уже играется в боковой панели и большом просмотре по `fileURL(path)#t=<loc>` (0.1.20–0.1.21, живой тест): asset
  protocol отдаёт видео и старт с момента работает. Muted-автозапуск Chromium разрешает — проверить гейтом.
- **Поведение взято из Imagus** (`Imagus-Mass-Download-Mod/src-mv3-overlay`, `content/content.js`): показ по 300 мс
  простоя (`delayOnIdle`), окно углом к курсору и растёт в свободную сторону (`placement: 0`), `scaleUp: false` — не
  растягивать сверх исходника, `fullspace: true` — при нехватке разворачивается под курсором. Закрытие — `mouseover`
  вне окна и карточки-триггера (`m_over`), а не таймеры ухода; `mouseleave` документа тоже скрывает. Окно остаётся
  живым, пока курсор над ним (в нём плеер). Это лечит «висит на полной сетке»: шаг из окна на любую карточку — уже
  `mouseover` вне, скрыть сразу.
- Свои клавиши окна перехватывают `Tab` (поле ↔ результаты) и `Space` (большой просмотр). **Решение: клавиатура —
  нативная (фокус в плеере, как у `<video controls>`); наше — только `Esc` закрывает. Tab до плеера не доходит, ховер
  фокус не забирает.**
- Файловые операции идут одной точкой — `operate()` → `file_operation` (Move/Copy/Delete). Пока плеер играет, файл
  открыт декодером WebView2: move/delete того же файла упрётся в sharing violation. **Решение: `operate()` закрывает
  плеер перед вызовом.**
- Правый клик: документный `contextmenu` (capture) прячет peek и открывает меню файла. **Решение: по карточке — меню
  файла (плеер закрывается); по плееру — нативное меню видео, не подавляем; `Pin` — только кнопкой.**
- Ничего в UI сегодня не уважает `prefers-reduced-motion`. **Решение: при reduce автозапуска нет** — кадр helper'а и
  Play.
- В вебвью уже есть localStorage (`frameFolder`). **Решение: `hoverVolume` там же** (не в Settings): ставим громкость при
  открытии, изменения ловим нативным `volumechange`.
- `renderContent()` пересобирает карточки: **незакреплённый плеер закрывается, закреплённый живёт** (у него нет привязки
  к карточке). Скролл списка — так же; колесо над плеером список не листает.
- Формат, который WebView2 не играет, в репозитории не представлен. **Решение: фикстур `broken.mp4` = MPEG-4 Part 2**
  (WebView2 не декодирует, ffmpeg helper'а отдаёт кадр) — им проверяется fallback в гейте.

Решения:

| Что | Решение |
|---|---|
| Где | Сетка главного окна. В таблице нет (строке негде встать сбоку); панель по хоткею и боковая панель — нет |
| Триггер | 300 мс простоя на карточке (`delayOnIdle`: таймер сбрасывается движением) |
| Позиция | Imagus `placement: 0`: угол окна у курсора, рост в свободную сторону; при нехватке — `fullspace` (под курсор); внутри `#content`; без отступа |
| Размер | Уменьшаем до доступной площади по пропорциям исходника; **сверх исходника не растягиваем** (`scaleUp: false`) |
| Старт | `max(0, loc − 2)`; у name-хита (нет `loc`) — с 0 |
| Звук | Всегда muted при открытии; громкость 25 % и запоминается (`hoverVolume`, нативный `volumechange`); звук — действием пользователя |
| Зацикливание | Только если длительность < 60 с |
| Один плеер | Один `<video>` на окно; при открытии — `pause` всем остальным видео страницы; при закрытии — `pause`, снять `src` |
| Управление | **Нативные `video controls`** (автоскрытие, стандартные иконки, колесо только на громкость). Поверх — только `Pin`, `Save frame`, `×`; всегда видимы, правый верхний угол, без своего автоскрытия |
| Имя | В окне нет (есть в результатах и на превью) |
| Закрытие | `pointerover` вне (окно ∪ карточка-триггер) → скрыть сразу; `mouseleave` документа → скрыть; `blur` → закрыть, если не закреплено; без таймеров |
| Закрепление | Только кнопка `Pin`; долгий правый клик не используется; нативное меню видео не подавляем; закреплено одно, новое заменяет |
| Клавиши | Нативные (фокус в плеере): Space/←/→/↑/↓ у `<video controls>`; наше — `Esc` закрывает; Tab до плеера не доходит |
| Reduce motion | Автозапуска нет: кадр helper'а и Play |
| Неиграемый кодек | Кадр helper'а + строка «Windows не проигрывает этот формат» + `Open`; повторно не пробуем |
| Контекстное меню | По карточке — меню файла (плеер закрывается); по плееру — нативное меню видео |
| Файловые операции | Перед Move/Copy/Delete плеер закрывается: файл открыт декодером |
| Что не делаем | Свои полосы seek/volume, перемотка колесом, скорости 0.5–2×, HLS/DASH, полный экран, второй плеер, ховер в таблице/панели |

Последствия и гейты:

- **Autoplay и звук**: muted-автозапуск разрешён; первый звук — жест на нативной кнопке громкости. Гейт: после открытия
  `video.muted === true`, `volume === 0.25`; громкость, выставленная нативной кнопкой, переживает следующий показ.
- **Кодеки** (проверено гейтом): `big.mp4` (H.264) играет, 2 с, зацикливается; `shots.ts` (MPEG-TS) **не** играет —
  `error` 4 приходит сразу, это штатный fallback-случай; `broken.mp4` (MPEG-4 Part 2) — тоже. Играющий фикстур для
  гейта — H.264-копия `shots.ts` (кадр на 9.5 с → старт 7.5 с).
- **Один декодер**: плеер создаётся только для наведённого; закрытие (уход/`pointerover` вне, `mouseleave`,
  перестройка результатов, скролл, большой просмотр) — `pause` + снять `src`; закреплённый переживает уход, на `blur`
  только пауза. Переход с играющего файла на неиграемый снимает старый `src` (иначе скрытый декодер продолжает играть).
- **Геометрия**: окно углом к курсору; курсор оказывается на углу окна, поэтому вход — сразу (шаг в его сторону), уход
  на любой другой элемент — сразу скрыть. Карточка под курсором частично накрыта — цена мгновенного входа; без
  смещения, иначе нужен таймер и возвращается «зависание». Окно не больше исходника; большое видео ужимается до
  площади.
- **Нативные контролы**: не стилизуются и прячутся сами (2000 мс); наш кластер `Pin/Save/×` всегда виден и не
  участвует в их автоскрытии — гонки «открылось/скрылось» нет. Колесо над плеером не листает список; нативная
  громкость колесом работает, перемотки колесом нет.
- **Файл занят**: пока плеер держит видео, move/delete того же файла невозможны — `operate()` закрывает плеер; рендер
  кадра helper'ом (Save frame) читает параллельно и не мешает.
- **Производительность**: `preload=metadata`, никакой предзагрузки; один файл за раз; 300 мс простоя отсекают проносы.
  Гейт: время до первого кадра на 4K-файле и отсутствие чтения всех видео подряд.
- **Конфликты**: перетаскивание выделения закрывает; клик по чекбоксу — нет; зум-контекстное меню карточки закрывает;
  по плееру — нативное меню видео; боковая панель и большой просмотр останавливаются, не закрываются.
- **Доступность**: нативные контролы дают клавиатуру и aria; у трёх наших кнопок `aria-label`; фокус не забирается,
  `Esc` закрывает, reduce-motion без автозапуска.
- **Тесты**: живой CDP с **настоящими** движениями мыши (`Input.dispatchMouseEvent`, не синтетика): появление по
  300 мс; окно не больше исходника и не выходит из `#content`; уход на другую карточку/пустое место/боковую панель →
  скрыть **сразу** (полная сетка видео в фикстурах); над плеером — живёт; нативные контролы на месте; muted и 25 %;
  старт `loc−2`; loop; кнопка `Pin` переживает уход; `×`; громкость запоминается; второй хувер заменяет; fallback
  `broken.mp4`; скриншот. Пометка в `docs/development-guide.md`.

**Сделано (2026-11-25, 0.1.23):** то же поведение в **списке** (таблица), где превью нужнее всего: `peekOnHover`вешается и на строку, поэтому картинка показывает превью, видео — тот же плеер, PDF — страницу (у `pdf`/`doc` —
пассаж). Колесо над строкой листает альбом сгруппированных картинок и страницы PDF (проверка «указатель внутри
элемента, на котором открыт peek», а не `closest('.cell')`), и список под ним не прокручивается. Гейт: строка
картинки, строка видео, строка PDF, колесо по PDF (Page 1 → 2) и по альбому (1 из 2 → 2 из 2); 34 проверки.

## 2. Последовательность кадров и сетка (после видео-хувера)

Два **отдельных** пункта меню видео-результата: `Extract frames…` и `Contact sheet…`.

Проверено по коду (2026-11-25), до реализации:

- `VideoExtractor.frame(at:)` уже умеет «кадр в момент» и знает правило MPEG-TS (у TS нет индекса: `-ss` без пре-ролла
  ничего не декодирует; код читает от `at−12` и потом доводит). Новые функции строятся на этом же правиле.
- `keyframes(...)` (индексация) — один проход ffmpeg: `fps=fps=…:start_time=…:round=up`, `scale=…`, `-q:v 3`,
  `%06d.jpg` в папку. Для последовательности тот же приём, но `-frames:v count` останавливает проход рано: «каждые 1 с»
  не декодирует весь фильм, «равномерно» — декодирует (это и так цена индексации).
- Сетка: **`tile` в вендоренном ffmpeg нет** — сборка минимальная (34 фильтра), `No such filter: 'tile'`; есть
  `hstack`, `vstack`, `pad`, `scale`, `fps`, `overlay`. **Решение:** сетка собирается `hstack` по рядам и `vstack` по
  рядам, неполный последний ряд добивается `pad=…:color=black`; пишет по-прежнему ffmpeg (путь вне ASCII — его забота,
  а не stb). Любой новый фильтр проверять `ffmpeg -filters` до использования.
- `render` занимает 2 слота и уходит в отдельный поток; остальные op'ы идут под общим `lock`. Значит новый op нельзя
  пускать через `handle` — он встанет в очередь поиска на минуты. **Своя серийная очередь** (один процесс, свой поток,
  как у `render`); второй запрос получает «an extraction is already running».
- Helper пишет только в свой temp (`<index>/previews`); файлы пользователя — территория shell (`save_frame` — образец).
  **Решение:** shell создаёт конечную папку/имя само и даёт helper'у свежую временную подпапку внутри неё; helper пишет
  только туда, shell переименовывает (та же папка — rename, без копирования гигабайтов). Ошибка → подпапка удаляется,
  конечное имя не появляется.
- Меню: `Save Frame at …`/`Copy Frame` уже добавляются для видео-хита (`window.js`, `oncontextmenu`); там же два новых
  пункта. Боковая панель: `media-actions` рядом с `Save frame` — две тихие кнопки.
- `ASK_OPS` (что страница может спросить у helper'а) намеренно не содержит `file_op`. **`frames` туда тоже не
  добавляем**: op пишет файлы, и путь выбирает shell (резерв имени, временная папка); право страницы на произвольную
  запись не нужно. Страница зовёт команду shell, она — helper.
- `frame_name`/`save_frame` в `main.rs` — образец имени и копирования; `pick_destination_folder` есть, но не нужен:
  папка выбирается правилом, а не диалогом.
- `shots.ts` — фикстур с известными цветами (`VideoTests`: R/G/B по 4 с); им проверяются и последовательность, и сетка.

Решения:

| Что | Решение |
|---|---|
| Где | Меню видео-результата: `Extract frames…`, `Contact sheet…`; боковая панель: кнопки `Frames…`/`Sheet…`; не панель по хоткею |
| Старт | `hit.loc` (у name-хита — 0); в диалоге виден и меняется («From 0:12») |
| Количество | 12 по умолчанию; последовательность до 120; сетка до 24 |
| Шаг | «Every 1 s» по умолчанию (короткий проход); «Evenly across the clip» — шаг = duration/N, декодирует весь клип (предупредить) |
| Размер | Нативный по умолчанию; вариант `1280 px` по длинной стороне; сетка — плитка 480 px |
| Выход последовательности | Папка `<видео> — frames` рядом с видео, `0001.jpg…` (порядок = время); занято — `(2)`; ничего не перезаписываем |
| Сетка | Отдельный пункт: один JPEG `<видео> — sheet.jpg` (занято — `(2)`), 4 колонки, ряды = ceil(n/4), последний ряд — чёрные плитки, без подписей |
| Обмен | `{"op":"frames","path","mode":"sequence\|sheet","start","count","step":"second\|evenly","pixels","out":"<temp>"}` → `{"files":[…],"ms":n}`; helper пишет в `out` (созданную shell'ом) |
| Очередь | Один op за раз, свой поток вне render-слотов и вне lock поиска; второй запрос — отказ с текстом |
| Отмена | Нет в v1; диалог показывает «Extracting…» и остаётся до ответа; окно не блокируется |
| Ошибки | ffmpeg ≠ 0, нет видео-потока, нет места — текст в диалоге; временная папка удалена; имя не занято |
| Индекс | Новые файлы появляются в корне → watcher индексирует их как обычные картинки (проверено в §1) |
| Что не делаем | Подписи времени на сетке, выбор папки диалогом, отмена, «каждый N-й кадр» по номеру |

Последствия и гейты:

- **Стоимость**: «Every 1 s» останавливается на N кадрах; «Evenly» декодирует весь клип (строка об этом для длинных
  файлов): на 4K это минуты. Времена файлов — `start + (i−1)·step`.
- **Диск**: 120×4K ≈ 1–2 ГБ; папка создаётся только после подтверждения — отмена до старта ничего не создаёт.
- **VFR**: `fps` привязывает кадры к сетке времени; для «evenly» шаг = duration/N (ffprobe). Проверить на VFR-файле.
- **TS/HEVC/MKV**: извлечение — ffmpeg, играть в WebView2 не требуется (это и есть путь для форматов, которые он не играет).
- **Безопасность**: helper не выбирает имён и не перезаписывает — конечное имя резервирует shell; временная подпапка
  `.digup-<pid>-<n>` уникальна на попытку и удаляется на любом исходе; брошенные после падения процесса остаются
  скрытыми (v1 их не сканирует).
- **Тесты**: Swift — последовательность на `shots.ts` (3 файла, R/G/B, времена внутри своих отрезков), сетка (один JPEG,
  3 плитки; 5 кадров — 4 + 1 с чёрной), ошибка на файле без видео; живой CDP — меню → диалог → папка/файл, имена, `(2)`
  при повторе, сетка; гейт.

**Сделано (2026-11-25, 0.1.23):** правка картинки живёт в **большом просмотре по Space**. Инструменты — в
**вертикальной рейке слева** (у вертикального кадра в широком окне свободны бока, поэтому высота остаётся картинке):
`Rotate left/right`, `Flip H/V`, `Resize`, `Crop`, `Format`, `Reset`, `Undo`; `Cancel` и `Save` — в шапке рядом с
размером. Поворот и флип рисуются на canvas сразу; кроп — **рамка на этом же canvas**, её будущий размер виден в шапке
(`2560 × 1440 → 800 × 600`), без второго окна; `Format` — панель там же (JPEG с качеством / PNG). Файл меняет только
`Save`: поворот, флип, кроп и размер — одна атомарная запись; `Cancel` не пишет ничего; `Reset` откатывает
неподтверждённое; `Undo` — последнюю сохранённую правку (`Ctrl+Z` тоже). Размер — **в пикселях по любой стороне** с
замком пропорций и строкой `Size 2560 × 1440 → 320 × 180`. JPEG поворачивается **без потерь** (`turbojpeg`:
DCT-коэффициенты; в ноте `(lossless)`; некратные MCU, кроп и resize — пиксельный путь). EXIF-ориентация впекается и
сбрасывается; EXIF/XMP/ICC/COM и PNG-текст сохраняются; PNG→JPG несёт промпты ComfyUI и A1111, альфа на белом;
конвертация уносит оригинал в Корзину и снимает его строку, watcher индексирует новый файл. Правая панель снова только
превью. Тесты: Rust 114; живой гейт большого редактора 30 проверок (рейка, превью поворота без записи, Save/Undo,
точный размер, кроп с рамкой на canvas, формат PNG с возвратом). Отложено: кнопка Undo в тосте (есть `Undo` в рейке и
`Ctrl+Z`). **Выпущено:** `v0.1.23`, 2026-11-25.

**Что дальше:** выходы, режимы, клавиатура и вид Crop — отдельный план `docs/image-editor-modes-plan.md` (собран из
проверок 0.1.23: слойный Esc/Cancel, подтверждение при закрытии с непримененным, панели Done/Cancel, возврат панелей
после Crop, `undo_state`, вид кропа без сдвига картинки). Реализовано и входит в `v0.1.23` (см. §7 там).

## 3. Правка изображений (после кадров) — на месте, без копий

Решение (2026-11-24): правка **на месте**. Человек видит в результатах перевёрнутую картинку и поворачивает её; видит
PNG на 40 МБ и сжимает его в JPG. Копия `<имя> — edited` — это второй файл, лишнее место и мусор в выдаче; правка — такая
же операция над файлом, как Move/Delete, а не «Сохранить как». Опасность осознанная; ниже — то, что не даёт ей стать
потерей данных.

Смотрел `d:\...\Image Sorter\`: Tauri + JS (`cropperjs`) + Rust (`image`, `turbojpeg`, `png`, `kamadak-exif`).

Проверенные факты (по коду):

- **Поворот 90°** — уже in-place: `backup_file` копирует оригинал в temp, `rotate_image` пишет файл, шаг кладётся в
  undo-историю. Для JPEG lossless через libjpeg-turbo, если блоки MCU совпадают, иначе перекодирование. Undo/redo —
  `swap_edit`: байты бэкапа кладутся рядом с живым файлом и переименовываются на место (атомарно); обычная запись —
  `fs::write` прямо в файл, то есть сбой посреди неё оставит половину (у нас так нельзя).
- **Кроп** (Cropper.js, координаты в натуральных пикселях), **конвертация PNG→JPG** с качеством и **сохранением
  метаданных** (JPEG APPn/COM: EXIF/XMP/ICC/комментарии/AI-промпты; PNG tEXt/zTXt/iTXt; альфа заливается белым; если
  метаданные не влезают в JPEG — файл **не** пишется, чтобы не терять данные), просмотр/правка метаданных.
- **Конвертация заменяет файл**: пишет `<имя>.jpg` рядом, оригинал отправляет в **Корзину** (`trash`), имя при
  коллизии получает `(1)`.
- **Resize в Image Sorter нет** (в коде только поворот/кроп/конвертация) — его добавляем сами
  (`image::DynamicImage::resize`/`thumbnail`).
- **EXIF orientation Image Sorter не нормализует** (в коде её нет). Для нас это обязательно: DigUp показывает картинку
  повёрнутой по тегу (`RGBImage.oriented`), и после поворота пикселей тег надо сбросить в 1, иначе просмотрщик повернёт
  ещё раз.

**Спайк (2026-11-25):** `image` 0.25 (`default-features = false`, bmp/gif/jpeg/png/tiff/webp), `png` 0.17 и
`kamadak-exif` 0.5 собрались в shell без нативки: холодная сборка 4 м 55 с (крейты), затем `--locked` — 2 м 58 с,
exe вырос на ~490 КБ (5 069 312 → 5 570 048). Ни CMake, ни DLL, ни правок упаковки — путь A (порт модулей Image
Sorter) остаётся; ffmpeg-запасной не нужен. Зависимости добавляются в коммите с кодом, а не раньше.

**Поворот без потерь (JPEG).** Коэффициенты DCT транспонируются, не декодируясь в пиксели: поворот 90/180/270 и флипы
выходят без потерь; кроп и resize без потерь невозможны. Инструмент — тот же libjpeg-turbo, что в Image Sorter, но
**крейтом `turbojpeg` 1.5** (`transform`, `perfect = true`), а не отдельным `jpegtran.exe`: `turbojpeg-sys` собирает
libjpeg-turbo статически через CMake (SIMD/NASM выключены — поворот это клик, не пакет), DLL рядом с exe не появляется,
поиска бинарника и дочернего процесса нет, на Linux работает так же. Спайк: сборка с крейтом 63 с (без VS-окружения),
exe +~700 КБ. Ориентация EXIF 2–8 печётся тем же проходом (её трансформ + просьба человека, каждый — отдельный lossless
трансформ), тег в файле правится на 1 до слияния сегментов. `perfect` проходит, когда **обе** стороны кратны MCU —
16 px при 4:2:0 (4032×3024, 6000×4000 — да; 1366×768 — нет) и 8 при 4:4:4; иначе `transform` отказывает, и тот же путь
перекодирует в q95 (молча срезать до 15 px нельзя). В тосте пишем, какой путь сработал: `Rotated … (lossless)` или без
пометки (перекодировано): человек иначе не узнает, потерял ли он качество. PNG без потерь и так (декод → пиксели →
энкод). Кроп/resize/формат идут пиксельным путём всегда.

Почему не копия и не «Сохранить как»: копия удваивает место ровно там, где человек как раз пытается его сэкономить, и
добавляет в выдачу файл, который он не просил. Правка — это то же, что Move/Delete: одно осознанное действие над файлом.

Почему не через helper: helper намеренно read-only (MCP-сервер только читает и отдаёт окна текста), а правка — файловая
операция shell'а, как Move/Delete: диалоги, Корзина и retry уже там. Модель и индекс в записи не участвуют.

Последствия и проверки:

- **Индекс.** Тот же путь: watcher видит изменение (размер/mtime) примерно через 2 с и просит sync; строка уходит в
  pending, пересчитываются вектор, phash, OCR и текст. Пока индекс не догнал, поиск по новому виду картинку не находит —
  это секунды; на сетевом диске, где watcher не работает, до опроса (5 мин) или ручного Rescan. Пишем это в описании
  функции, чтобы «повернул, а поиск не видит» не выглядело багом. Если индексатор читал файл ровно в момент записи, он
  запишет старые размер/mtime — следующий sync увидит расхождение и прочитает файл ещё раз (самоисправление).
- **Свежесть в окне.** Сразу после записи страница перезапрашивает картинку с `?v=<mtime>` (спайк: принимает ли asset
  protocol query); если нет — правая панель и большой просмотр берут `render` (data-URL, уже есть), сетка обновится
  следующим поиском.
- **Одновременная индексация.** Индексатор может читать файл в этот момент: переименование на место упадёт с sharing
  violation — повторяем (retry, как в `file_ops`), поверх открытого файла не пишем. Читатель с открытым дескриптором
  дочитает старые байты: он увидит либо старый, либо новый файл, не половину.
- **Свободное место.** Temp-файл рядом требует размера результата поверх оригинала на том же диске; ошибка записи —
  оригинал цел, temp удалён.
- **Права.** Read-only, занятый файл, нет прав — текст ошибки, ничего не записано. Симлинк: сначала `canonicalize`,
  пишем в цель, ссылка остаётся ссылкой.
- **Корень.** Правим только файл, который показывает окно (вне корней тоже можно, как `save_frame`); в индекс инструмент
  не пишет.
- **Конвертация на Linux.** Корзина в shell — Windows (`SHFileOperationW`); на других системах v1 предлагает только
  правку в том же формате, а формат-конвертация говорит «не на этой системе». `trash`-крейт — отдельным шагом.
- **Доступность.** Лист: фокус-ловушка, Esc отменяет без записи, у кнопок `aria-label`, ошибки текстом (не только
  цветом), «Undo» в тосте фокусируемо.

Тесты:

- Портируемые юнит-тесты Image Sorter: поворот/кроп/метаданные/альфа/«не влезло — не пишем» + resize; orientation 6 →
  ровно один поворот и тег 1; PNG→JPG с prompt/workflow.
- Атомарность: сбой записи temp (read-only папка, переполнение) → оригинал побайтово тот же, temp не остался.
- Поворот JPEG: 64×48 (кратно MCU) через `turbojpeg` → пиксели до/после идентичны (сверка декодированных кадров),
  orientation = 1; 17×9 → `perfect` отказал, сработал пиксельный путь; orientation 6 + «поворот вправо» → ровно один
  поворот, не два.
- Undo: байты вернулись один в один; стек ограничен 10, старейший бэкап удалён.
- Индекс (живой): повернуть картинку из выдачи, дождаться sync, найти по новому виду (вектор обновился), phash другой;
  окно не показывает старый кадр.
- Конвертация (живой): PNG в Корзине, JPG на месте, строка переехала, поиск находит; `<имя>.jpg` уже есть → отказ.
- Живой UI (CDP): `Rotate right` из меню пишет файл; `Edit…` кроп → точный размер; Esc ничего не пишет.

## 4. Порядок, гейты, риски

1. **Видео-хувер** (0.1.22): UI + живой CDP-гейт; helper не меняется.
2. **Кадры + сетка**: новый op helper'а → полный zip; тест на `shots.ts` + живой; гейт.
3. **Правка изображений**: спайк зависимостей и lossless-поворота → перенос модулей + меню `Rotate`/лист + тесты;
   правка **на месте**.
   shell-only невозможен, если версия MCP меняется вместе с приложением (она вшита в helper) — каждый релиз сейчас
   полный zip; это отдельное наблюдение, не часть инструментов.

Риски:

- Видео-хувер: WebView2 не играет часть форматов (fallback обязателен); autoplay со звуком (muted по умолчанию
  снимает); конфликт долгого правого клика с меню строки (решено: только по окну); один декодер.
- Кадры: VFR/длинные 4K (время/диск); потолок N; сетка без подписей (иначе шрифт).
- Правка: на месте разрушительна — рельсы: одна атомарная запись, undo на 10, Корзина при конвертации, отказ на
  read-only/анимации/HEIC. Поворот JPEG без потерь есть, но не для всех размеров: некратные MCU (16 px при 4:2:0)
  перекодируются в q95 — пометки `(lossless)` в тосте тогда нет, и это видно. Кроп/resize без потерь невозможны. Без
  нормализации EXIF orientation получим двойной поворот. Индекс догоняет через watcher (~2 с), на сетевых дисках — до
  5 мин. `turbojpeg` тянет CMake и компиляцию C в каждую сборку shell (SIMD выключен; 63 с на этой машине); если
  libjpeg-turbo не соберётся на чужой машине — остаётся пиксельный путь, lossless просто не включается.

## 5. Панель по хоткею: баг углов (исправлено)

- **Причина (по пикселям скриншота):** углы панели скруглены (`.panel`, radius 18), но окно с `shadow(true)` рисует
  **прямоугольную серую рамку** по своим границам; между ней и скруглением видны «треугольники» — это фон/край окна, а
  не панель.
- **Фикс:** у окна панели `shadow(false)` — системная прямоугольная тень/рамка уходит, остаётся только скруглённая
  панель (фон окна прозрачный). **Проверено** снимком экрана: до — по границе окна шла серая линия 129, а в углу
  (24,24) был прямоугольный край; после — (24,24) чёрный (прозрачно), (24,40)/(40,24) 215 (собственная рамка панели),
  прямоугольника нет, только скругление.
- **Последствие:** у панели больше нет системной тени (на Windows она и была прямоугольной); при желании тень можно
  нарисовать CSS внутри окна с полями — отдельным решением, не сейчас.
- **Тест:** `.build/panel-shot.ps1` (запускает панель с `--debug-show` на scratch-настройках, снимает область окна) +
  `.build/panel-corners.png`, `.build/panel-tl.png`/`panel-tl-after.png`; повторять при изменениях окна панели.
