# Медиа-инструменты: видео-хувер, кадры, правка изображений

**Статус:** план 2026-11-24. Порядок работ: **видео-хувер** → **последовательность кадров и сетка** → **правка
изображений**. Ниже — предварительные решения (не предположения: где факт не проверен, это сказано явно), последствия
для остального приложения и список спайков, которые надо провести до кода.

## 0. Что уже есть

- Правая панель главного окна: у видео кадр + ▶, `Save frame` до и после проигрывания (0.1.21).
- Меню видео-результата: `Save Frame at …` (момент совпадения) и `Copy Frame` (PNG в буфер) — 0.1.20.
- Space в главном окне: большой просмотр, видео играет с момента, `Save frame` берёт текущий кадр.
- Панель по хоткею (`index.html` + `panel.js`): быстрый поиск «поверх» других программ, свой маленький список и свой
  Space-просмотр. **Инструменты туда не добавляем** (транзитная, клавиатурная поверхность).
- Панель по хоткею: **визуальный баг углов исправлен** — причина и проверка в §5.

## 1. Видео-хувер (следующее)

Всплывающий под курсором плеер в главном окне результатов — то, что в Imagus-Mass-Download-Mod сделано для видео.

Предварительные решения:

| Что | Решение |
|---|---|
| Где | Главное окно, сетка и таблица; не панель по хоткею, не боковая панель (там уже есть) |
| Триггер | Указатель на карточке/строке видео ≥ 300 мс (как у картинок); уход — закрыть |
| Позиция | Справа от карточки с зазором 12 px; если не влезает — слева; по высоте — в пределах окна (12 px от краёв), не под курсором |
| Размер | До 480×270 (16:9), другие пропорции — по исходнику с теми же пределами |
| Старт | `max(0, loc − 2)` — две секунды контекста; у name-хита (нет `loc`) — с 0 |
| Звук | Всегда **muted** при открытии; громкость — запомненная, по умолчанию **25 %**; звук только по действию пользователя |
| Зацикливание | Только если длительность < 60 с |
| Один плеер | Один `<video>` на всё окно; при открытии остановить боковую панель/большой просмотр; при закрытии — `pause`, снять `src` |
| Управление | Пауза/играть, время, полоса перемотки (клик/перетаскивание), громкость+mute, `Pin`, `Save frame` (текущий), `×` |
| Указатель | Окно интерактивно; оно не накрывает карточку (позиция сбоку), уход в него не закрывает, уход из него — закрывает, если не закреплено |
| Закрепление | Долгий правый клик (≥ 450 мс) **по уже показанному окну** — переключает `pinned`; закреплённое не закрывается, таскается за шапку; закреплено одно (новое заменяет); отпускание правой кнопки не отменяет |
| Клавиши | Только когда фокус в окне: Space, ←/→ ±5 с (Shift ×3), ↑/↓ громкость, M mute, Esc закрыть; в поле поиска не перехватывать |
| Неиграемый кодек | Показать кадр helper'а + `Open`/`Save frame` и одну строку «Windows не проигрывает этот формат»; не повторять попытку |
| Контекстное меню | Правый клик по карточке по-прежнему меню файла; долгий правый клик на карточке **не** используется — только на окне |
| Что не делаем | Скорости 0.5–2×, HLS/DASH, полноэкранный режим, второй плеер одновременно |

Последствия и проверки (спайк до кода):

- **Autoplay в WebView2**: muted-автозапуск разрешён; громкость до первого жеста может быть заблокирована — проверить
  на нашем окне (0.1.21, Windows 10). Если звук не стартует до клика — кнопка mute остаётся, но первый unmute требует
  клика (это и так жест пользователя).
- **Кодеки**: `<video>` через Media Foundation играет MP4/H.264/AAC, WebM/VP9; MKV/HEVC/TS могут не играть. Для
  проверки — реальные файлы пользователя; при ошибке `error` — fallback выше, без зависаний.
- **Один декодер**: 120 карточек в сетке — плеер создаётся только для наведённой; при уходе `pause`+`removeAttribute`.
  В фоне (окно не в фокусе, `visibilitychange`) — пауза.
- **Производительность**: старт кадра с HDD — десятки мс; `preload=metadata`; не грузить все видео.
- **Конфликты**: перетаскивание файла (drag-out), меню, выделение — не трогаем; окно не накрывает карточку.
- **Доступность**: у кнопок `aria-label`, окно не забирает фокус при показе; при закреплении — фокусируемо, Esc закрывает.
- **Тесты**: живой CDP (появление, muted, громкость 25 %, старт `loc−2`, seek, pin переживает уход, Esc, второй хувер
  заменяет, fallback) + гейт после сборки.

## 2. Последовательность кадров и сетка (после видео-хувера)

Два **отдельных** пункта меню видео-результата (как договорились): `Extract frames…` и `Contact sheet…`.

Предварительные решения:

| Что | Решение |
|---|---|
| Где | Меню видео-результата и кнопка `Frames…` в правой панели; не панель по хоткею |
| Старт | `hit.loc` (или текущий кадр боковой панели/большого просмотра, если открыт тот же файл) |
| Количество | 12 по умолчанию; максимум 120 |
| Шаг | «Каждые 1 с» по умолчанию; второй вариант — «равномерно по клипу» (N кадров на длительность) |
| Размер | Нативный по умолчанию; вариант 1280 px по длинной стороне |
| Выход последовательности | Папка `<видео> — frames` рядом с видео, файлы `0001.jpg…`; если папка есть — `— frames (2)`; ничего не перезаписывать |
| Сетка | Отдельный пункт; один JPEG `<видео> — sheet.jpg`; 4 колонки, до 24 кадров; без подписей времени в v1 (шрифт/лицензия не нужны) |
| Реализация | Один новый op helper'а `frames` (ffmpeg одним процессом: `-ss`, `fps`/`select`, `-frames:v`, для сетки `tile`), в отдельном потоке как `render`; ответ — папка/файл/число/ошибка |
| Ограничения | Нет отмены в v1 (один процесс; кнопка «Extracting…»); потолок N; предупредить об объёме (120×4K ≈ 1–2 ГБ) |
| Совместимость | Кадры извлекает ffmpeg — работает и там, где WebView2 не играет (MKV/HEVC/TS) |

Последствия:

- Новые файлы лежат внутри выбранного корня → обычный обход их проиндексирует (если правила папки включают картинки);
  индекс пишет не инструмент, а индексатор. Если папка исключена/`skipTypes` — копии не попадут в индекс, это выбор
  пользователя.
- Диск: последовательность — это N файлов; сетка — один. Потолки и предупреждение о размере обязательны.
- VFR-видео: `fps`-фильтр привязывает кадры к сетке времени; для «равномерно по клипу» шаг = duration/N. Проверить на
  реальном VFR-файле.
- `shots.ts` (3 цветных кадра по 4 с) — эталон для теста: 3 кадра, цвета R/G/B, времена внутри своих отрезков; сетка —
  один JPEG с 3 плитками. Живой тест: 2560×1440, 6 кадров, нативный размер, имена, отсутствие перезаписи.

## 3. Правка изображений (после кадров)

Смотрел `d:\...\Image Sorter\`: Tauri + JS (`cropperjs`) + Rust (`image`, `turbojpeg`, `png`, `kamadak-exif`).

Проверенные факты (по коду):

- Есть **поворот на 90°** (`rotate_image`, для JPEG — lossless через libjpeg-turbo, если блоки MCU совпадают; иначе
  перекодирование), **кроп** (Cropper.js, координаты в натуральных пикселях), **конвертация PNG→JPG** с качеством,
  **сохранение метаданных** (JPEG APPn/COM: EXIF/XMP/ICC/комментарии/AI-промпты; PNG tEXt/zTXt/iTXt; альфа
  заливается белым; если метаданные не влезают в JPEG — файл **не** пишется, чтобы не терять данные), просмотр/правка
  метаданных, undo/redo.
- **Resize в Image Sorter нет** (в коде только поворот/кроп/конвертация) — его добавляем сами, это малая функция
  (`image::DynamicImage::resize`/`thumbnail`).

Предварительные решения для DigUp:

| Что | Решение |
|---|---|
| Безопасность | **Только копия**: оригинал не трогаем; никакого undo не нужно; имя по умолчанию `<имя> — edited.<ext>`, диалог сохранения, ничего не перезаписывать |
| Где | Модальный лист из правой панели (`Edit a copy…`) и из меню результата; не панель по хоткею, не хувер |
| Инструменты v1 | Поворот 90°/флип, кроп (Cropper.js), resize по длинной стороне/проценту, формат JPEG (качество 90)/PNG |
| Метаданные | Сохранять EXIF/ICC/PNG-текст/JPEG-комментарии; ориентацию нормализовать; если в целевой формат не влезает — отказать и предложить PNG (правило Image Sorter) |
| Форматы | Вход: JPEG/PNG/WebP/BMP/TIFF/GIF (что умеет `image`); **HEIC/RAW не редактируем** — открываем в системе; выход: JPEG/PNG; WebP/AVIF — только если спайк подтвердит энкодер и нужность |
| Реализация | Перенести модули Image Sorter (`image_proc`, `jpeg_meta`, `png_meta`, при необходимости `exif_writer`) в shell; зависимости `image`, `turbojpeg`, `png`, `kamadak-exif`; `cropper.min.js` (MIT) вендорим в `shell/ui/vendor` |
| Спайк до кода | Собрать эти зависимости в нашем shell/пакетном окружении (Windows, MSVC, CMake; Linux), замерить время сборки и размер; прогнать тесты Image Sorter в нашей копии; проверить Cropper.js в нашей CSP/плоском UI |
| Если спайк провалится | Запасной путь — ffmpeg для поворота/кропа/resize/конвертации **без сохранения метаданных**, с явным предупреждением; тогда функции урезаны, но зависимостей нет. Решение принимать по результату спайка, не заранее |
| Индекс | Копия — новый файл; её подхватит обход (если правила папки включают картинки); инструмент в индекс не пишет; оригинал и его строка не меняются |
| Тесты | Портированные тесты Image Sorter (поворот/кроп/метаданные/альфа) + resize; живой UI (кроп, поворот, save copy); оригинал побайтово не изменён; копия появилась и проиндексирована |

Почему не в панели по хоткею и не в хувере: панель — быстрый поиск; хувер — просмотр. Редактор — лист главного окна с
местом под изображение и контролы.

## 4. Порядок, гейты, риски

1. **Видео-хувер** (0.1.22): UI + живой CDP-гейт; helper не меняется.
2. **Кадры + сетка**: новый op helper'а → полный zip; тест на `shots.ts` + живой; гейт.
3. **Правка изображений**: спайк зависимостей → перенос модулей + лист + тесты; shell-only невозможен, если версия
   MCP меняется вместе с приложением (она вшита в helper) — каждый релиз сейчас полный zip; это отдельное наблюдение,
   не часть инструментов.

Риски:

- Видео-хувер: WebView2 не играет часть форматов (fallback обязателен); autoplay со звуком (muted по умолчанию
  снимает); конфликт долгого правого клика с меню строки (решено: только по окну); один декодер.
- Кадры: VFR/длинные 4K (время/диск); потолок N; сетка без подписей (иначе шрифт).
- Правка: зависимости и их сборка (turbojpeg нативно); метаданные; HEIC/RAW; Cropper.js в плоском UI; «копия» вместо
  in-place (осознанно).

## 5. Панель по хоткею: баг углов (исправлено)

- **Причина (по пикселям скриншота):** углы панели скруглены (`.panel`, radius 18), но окно с `shadow(true)` рисует
  **прямоугольную серую рамку** по своим границам; между ней и скруглением видны «треугольники» — это фон/край окна, а
  не панель.
- **Фикс:** у окна панели `shadow(false)` — системная прямоугольная тень/рамка уходит, остаётся только скруглённая
  панель (фон окна прозрачный). **Проверено** снимком экрана: до — по границе окна шла серая линия 129, а в углу
  (24,24) был прямоугольный край; после — (24,24) чёрный (прозрачно), (24,40)/(40,24) 215 (собственная рамка панели),
  прямоугольника нет, только скругление.
- **Последствие:** у панели больше нет системной тени (на Windows она и была прямоугольной); при желании тень можно
  нарисовать CSS внутри окна с полями — отдельным решением, не сейчас.
- **Тест:** `.build/panel-shot.ps1` (запускает панель с `--debug-show` на scratch-настройках, снимает область окна) +
  `.build/panel-corners.png`, `.build/panel-tl.png`/`panel-tl-after.png`; повторять при изменениях окна панели.
