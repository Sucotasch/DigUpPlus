# Per-folder indexing rules: top-level-only and kind filters

**Дата:** 2026-11-04. **Статус:** план к исполнению (согласован с владельцем форка). Все решения проверены по коду
(разведка 2026-11-04, см. «Проверено по коду» у каждого этапа). Исполнитель: основной или младший агент.
Предшественники: `docs/roadmap-plan.md` (контекст), `docs/file-operations-plan.md` (образец стиля).

## Цель

Два пер-корневых правила индексации, живущих рядом в Settings → Folders:

1. **Типы на папку** — «в этой папке только изображения, в той только видео».
2. **Только верхний уровень** — «не ходить вглубь этой папки».

Почему в одном документе: оба — пер-корневые правила обхода, едут через одну проводку (Settings → шелл → аргументы
helper'а → Crawler), один тестовый набор и один релиз. Поиск отдельно не настраивается — он ищет по индексу;
правило применяется в краулере, и выдача следует за индексом (см. «Отвергнутые решения»).

## Проверено по коду (факты, на которых стоят решения)

- `Crawler.crawl` обходит корни **по одному** (`for input in roots`, Crawler.swift:68); classify получает файл в
  контексте текущего корня (`foundRoot[url.path] = root.path`, :170). Правило корня можно применить в месте classify
  без новой архитектуры.
- `DirectoryWalk.skipDescendants()` (Files+Portable.swift:196: `opened = nil`) — готовая точка для shallow-прохода:
  после обработки самого корня снять «открытую» папку, и ход остановится на первом уровне.
- Sync сам удаляет выпавшие строки: кандидат не в `seen` → `store.delete(row.id)` (Indexer.swift:169-172). Смена
  правила = **resync, не reindex**: fingerprint не затрагивается (Model.swift:80 — только бюджеты векторов).
- Проводка аргументов до helper'а уже есть: `folder_arguments()` → `index_launch()`/`search_launch()` (main.rs:239);
  roots едут как positional (main.swift:490, `Part.roots`), skipped как `--exclude`.
- Теги: `FFmpeg.run/output` (Media+Portable.swift:26-50) — готовый Process-паттерн; ffprobe в Vendor ищется через
  `find("ffprobe")` (:7-8). Фаза 3 не добавляет ни одного бинарника.
- Estimate идёт через тот же `Crawler.crawl` (main.swift:279) — estimator получит правила бесплатно, если флаг
  приедет и в estimate (урок #153: прогноз не должен расходиться с фактом).
- UI: строки папок рисует `folderRow()` (settings.js:208); команды вида `set_skipped` (main.rs:2537) — образец
  «поменял settings → save → apply_folders».

## Отвергнутые решения (чтобы не переобсуждать)

- **Раздельные правила для индексации и поиска** — нет: поиск ищет по индексу; «фильтр поверх индексированных»
  делает числа на чипах зависимыми от невидимого фильтра (тот класс UX-обмана, который мы сняли с All-files).
- **Fingerprint при смене правил** — нет: правило не меняет векторы; reindex уничтожил бы индекс без причины.
  Resync сам сходится к новому правилу.
- **Отдельный crawl-проход на корень с пост-фильтрацией** — нет: обход по одному корню уже есть; пост-фильтр дал бы
  неверные `leftOut`-репорты («not read» вместо «of a kind this folder doesn't index»).
- **Плагины с пользовательским кодом** (фаза 4 из обсуждения) — отложено: песочница, ABI, privacy-контракт;
  декларативные правила закрывают 90% спроса. См. «Фаза 4 (отложено)».

## Фаза 1 — kind-фильтры и top-level-only на корень (ядро)

**Решение.** Новая секция settings:

```json
"rootRules": {
  "D:/Photos":  { "kinds": ["image", "screenshot"], "shallow": false },
  "D:/Records": { "kinds": ["audio"],               "shallow": true  }
}
```

- `kinds` отсутствует или пусто → папка индексируется как сейчас (всё). `shallow: true` → не спускаться ниже корня.
- Данные — на Settings (camelCase), НЕ в IndexOptions-fingerprint.

### 1.1 Engine: правило до краулера

- `IndexOptions` + два поля: `rootRules: [RootRule]`, где `RootRule { root: String; kinds: Set<FileKind>?; shallow: Bool }`
  (Model.swift; Sendable, вне fingerprint).
- `Crawler.crawl`: в цикле по корням найти правило текущего корня (longest-prefix не нужен — правила пишутся на сами
  корни); передать его в локальную обёртку classify:
  - `kinds` заданы → файлы корня, чей вид не входит, → `.skip("of a kind this folder doesn't index")` (новая
    причина, попадает в `leftOut`-репорт Settings);
  - `shallow` → сразу после первого уровня корня: `walker.skipDescendants()` после обработки корневой папки.
    Реализация: флаг в visit(), что текущий объект — прямой ребёнок корня и shallow, → skipDescendants.
- Estimator получает те же правила (args уже общие) — прогноз сходится с фактом автоматически.

### 1.2 CLI: разбор аргументов

- `--root-rule <json>` (повторяемый, `Arguments.repeated`): `{"root":"D:/Photos","kinds":["image"],"shallow":true}`.
  Парсинг в `Arguments`, маппинг в `IndexOptions.rootRules` (main.swift:110, рядом с `--include-datasets`).
- `index-service`/`estimate` получают одинаково; код-search флаг игнорирует (code-корни имеют свои правила позже,
  не в этой фазе).

### 1.3 Shell: settings → helper

- `Settings.rootRules: Option<serde_json::Value>` (сырой JSON — не лепить типы Rust ради одного поля; валидирует
  helper).
- `folder_arguments()` (main.rs:239) добавляет `--root-rule <json>` на каждый элемент. Оба launch'а (index +
  search) получают автоматически; estimate — та же функция.
- Команда `set_root_rules(app, shell, rules: Value)` по образцу `set_skipped` (main.rs:2537): save + apply_folders.

### 1.4 UI: Settings → Folders

- В `folderRow()` (settings.js:208) — кнопка «Rules» рядом с Remove; поповер с чекбоксами видов
  (Images/Screenshots/Documents/Video/Audio) + «Top level only».
- Пустое правило = «всё, как сейчас» — чипы на правилах не рисуются, когда пусто.

### 1.5 Тесты

- Engine (Swift Testing): краулер с rootRules — файл вида вне списка → skip-причина в `report.leftOut`; shallow —
  файл на первом уровне индексируется, в подпапке — нет; пустое правило = поведение без изменений (регресс).
- Sync-сходимость: индекс с файлами по старому правилу → сузили kinds → sync → строки удалены, summary сходится.
- Shell (cargo): `folder_arguments` рендерит `--root-rule`; сериализация туда-обратно.
- Estimator: сузили kinds → `estimate` падает по секундам соответственно.

### 1.6 Критерии приёмки

1. Папка A с kinds=["image"]: видео-файлы внутри не индексируются, в leftOut видна причина; Documents-чип не врёт.
2. Папка B shallow: файлы в подпапках не индексируются, топ-уровень — да.
3. Снятие правила → resync возвращает полноту индекса без reindex и без потери векторов у вернувшихся файлов
   (их row.id сохранился? НЕТ — удалённые строки пересоздаются; косвенно проверяем, что пере-эмбеддинг только
   для вернувшихся файлов, а не всей папки).
4. Watcher: новый файл в папке A не того вида не появляется в выдаче; того вида — появляется.
5. Estimate сходится с фактом первой проходки (±10%).
6. Полный набор тестов зелёный; `evals/*.json` без регрессий (правила не заданы).

## Фаза 3 — теги аудио (mp3 и соседи): декларативно, не плагин

**Решение.** `typeRules` — продолжение rootRules в settings:

```json
"typeRules": { ".mp3": "tags", ".wav": "skip", ".pdf": "full" }
```

- Режимы: `full` (как сейчас; дефолт), `tags` (ffprobe → title/artist/album/genre/year в FTS + имя файла; **без**
  эмбеддинга звука), `skip` (не читать вовсе; причина в leftOut «skipped by type rule»).
- Проводка: `--type-rule <ext>=<mode>` (повторяемый), `IndexOptions.typeRules: [String: TypeRule]`.
- Экстрактор: `MediaTags.extract(path)` через `FFmpeg.output(ffprobe, ["-show_entries", "format_tags"])`; JSON в
  строку FTS-сегмента `modality: .text`; **fingerprint: «tags1»** — при смене режима .mp3 full→tags и обратно
  нужен reindex этого вида (это честно: меняется содержание сегментов). Точнее: typeRules ДОЛЖНЫ входить в
  fingerprint (в отличие от rootRules) — иначе индекс смешает два режима для одного расширения. Решение: fingerprint
  = `... tags(.mp3=tags,.wav=skip)` (сортированный канонический вид) — смена правила = авто-reindex по fingerprint.
- UI: Settings → Folders, «File type rules» — пикер режима на расширение (редактируемое поле + селектор).
- Тесты: ffprobe-теги на фикстуре .mp3 (создаётся ffmpeg'ом в тесте), skip-режим, fingerprint-переход.

## Фаза 4 (отложено) — плагины

## Риски и их обработка

- **Смешанные правила вложенных корней** (папка внутри папки с другим правилом): правило ближайшего корня
  (longest-prefix), как уже делает контекст в crawl (:73-75). Тест на вложенный случай обязателен.
- **Rule подустарела** (папка удалена): folderRow-правило живёт в JSON по пути; `remove_folder` (main.rs:2406)
  обязан чистить соответствующий rootRules-элемент (иначе мусор навсегда). Тест.
- **`--root-rule` в позиционных корнях dev-запуска** (`--roots`): правила из Settings не едут в dev-запуск, где
  корни заданы флагом — правила и корни всегда из одного источника (settings), иначе путаница. Документировать.
- **Производительность**: не должна измениться — одно dict-lookup на корень (краулер и так раз в корень), classify
  без изменений для папок без правил.
- **leftOut-репорт**: новые причины («of a kind…», «skipped by type rule») попадают в существующую карту причин
  Settings (reasonLines, settings.js:186+) — добавить строки-переводы.
